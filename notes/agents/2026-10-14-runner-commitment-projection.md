# Runner commitment projection loop

- Unexpected hurdle: the source collections have no production write owner in this repository, and the initial `listForRunner` query read records from multiple collections.
- Diagnosis: repository search and infrastructure docs showed the search function is read-only; therefore switching the reader alone would point at an unmaintained projection.
- Chosen fix: make Firestore write triggers the projection owner for assignment, segment, and point changes; refresh affected projections transactionally; add idempotent backfill; keep rollout disabled by default and retain the canonical reader until deployment and backfill evidence exist.
- Nightly benchmark: run Playwright on the canonical reader, enable the projection in the ephemeral GCP test environment afterward, seed 100 assignments, explicitly backfill them, and label the latency artifact with its read model and processed count.
- GCP hurdle: the first live `gcp-test` deployment reached fixture seeding, then failed because `scripts/gcp-test-fixture.js` omitted the required `saveRenderedPage` dependency; the projection measurement was therefore skipped.
- Diagnosis/fix: followed the stack to `createRenderContents` and extracted its Cloud Storage adapter into `save-rendered-page.js`, shared by the production GCF adapter and the GCP fixture. This avoids two implementations and ensures seeded pages use production save semantics.
- Second GCP hurdle: run `38603133807` deployed Terraform and cleaned up successfully, then fixture seeding failed because the renderer also requires response-header, response-send, and error-log adapters. It exposed that the fixture called the renderer without running it inside `bindEffectBoundary`.
- Diagnosis/fix: use the same `response-effects.js` adapters as the production wrapper, and invoke the fixture renderer through its explicit effects boundary.
- Third GCP hurdle: run `38609250481` deployed Terraform and cleaned up successfully, then fixture seeding reached `renderSeededStoryPages` and failed with `saveStorageFile must be a function`.
- Diagnosis/fix: the second fixture phase called `createRenderVariant` without the production Storage and Firestore write adapters and without an allow-effects invocation boundary. Inject `saveStorageFile`, `setFirestoreDocument`, and `updateFirestoreDocument` from the production adapter module, then invoke each render through `bindEffectBoundary`.
- Verification: focused fixture test passed (4/4); `npm run build:cloud` passed; `npm run check` passed all 10 gates, including 11 local E2E tests and zero clones. The full check log is `.tmp/projection-render-variant-check.log`.
- Fourth GCP hurdle: run `38614457034` completed fixture seeding, but the Playwright Cloud Run task exited 1 before uploading `test-results`. The workflow's Cloud Logging query returned no rows because it filtered on `resource.labels.execution_name`; the execution's `logUri` specifies `labels."run.googleapis.com/execution_name"`.
- Diagnosis/fix: update both failure log queries to use the execution label from `logUri`, and add a workflow regression assertion. The focused workflow suite passed (1 suite, 11 tests); `npm run check` passed all 10 gates.
- Fifth GCP hurdle: run `38619162337` on the log-query fix reached the Playwright job and captured two failures. Moderation's browser import requested `/adapters/allow-effects.js`, which Terraform did not upload. The payment E2E expected an unmatched Stripe `charge.refunded` event to deduct credits, contrary to production's explicit external-refund quarantine contract. Terraform teardown and the separate cleanup job succeeded.
- Diagnosis/fix: add the shared adapter to the static site object map at the imported URL and cover that deployment path. Update the payment E2E to assert quarantine and unchanged credit balance/event history. Focused asset test passed (1 suite, 11 tests); `npm run check` passed all 10 gates, including 11 local E2E tests and zero clones.
