# Toy input and output order

Every generated toy includes a Swap input/output button in the controls row below input. `toyLayout.js` owns an immutable logical order object; input includes its control row. The handler stores that model per article and changes it with `swapToySections`. `presenters/toyLayout.js` binds existing key/value nodes once, then projects the model order into the DOM at a stable boundary. DOM classes and button attributes never determine logical state. Keeping node identity preserves event listeners, capture state, and the current canvas. The button stays below input in both layouts; aria-pressed is derived from the model. Metadata and post content retain their order. Tests exercise model transitions independently and verify projection is idempotent even after stale DOM attributes or misplaced nodes.

The full check exposed two long exact HTML expectations in `test/generator/generator.test.js`; one expectation contains two toys. Update every toy occurrence when adding shared controls, then run that fixture suite with Node's `--experimental-vm-modules` flag before the aggregate coverage runner.
