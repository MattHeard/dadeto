# Atlas held-out accuracy persistence retrospective

- **Unexpected hurdle:** The new append helper crashed on a null evidence graph because the existing graph validator dereferenced collections before checking the graph shape. The first focused run also showed that malformed-input tests needed to exercise the validator's public failure contract rather than assume all callers provide a typed graph.
- **Diagnosis:** Focused Jest exposed the null dereference. Changed-core coverage then identified missing branches for absent legacy collections and an already-invalid evaluation collection. The fast check's TSDoc gate separately found widened success/failure unions and implicit callback/report types.
- **Chosen fix:** Make `validateEvidenceGraphV1` return a stable `invalid-graph` result for non-object inputs; explicitly type the V4 result unions, collection keys and report summaries; test V2/V3 normalization, V4 round trips, invalid schema/IDs/references, unchanged input, and service token forwarding. Use deterministic synthetic measurements where mechanistic MSE is worse than sampling MSE and assert the negative result survives persistence.

These are local checks; exact-head GitHub Full Check and Terraform Validate remain authoritative after push.
- **Next-time guidance:** For new persistence paths, begin with malformed-container tests and legacy normalization cases before extending the writer. Keep schema adapters injectable in tests; include a durable negative-result fixture, not only a successful outcome.
