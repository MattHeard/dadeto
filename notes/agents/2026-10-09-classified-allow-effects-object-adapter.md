# Classified AllowEffects object adapter

- Unexpected hurdle: native Storage methods live on a prototype, while invoking a property getter during adapter construction could itself be observable. The initial architecture gate also treated every non-core file over 50 lines as an entrypoint wrapper.
- Diagnosis: method lookup must walk data descriptors without invoking accessors, then bind the selected function to its original object. The shared reusable adapter is implementation code rather than an environment wrapper; browser-specific Storage composition did not belong in the already thin browser effect-adapters module.
- Chosen fix: added the explicitly classified `adaptAllowEffectsBag` factory beside `requireAllowEffects`. It builds a frozen null-prototype object, exposes only selected query/effect methods, binds methods at each nested level, rejects missing/invalid/unknown/accessor/non-method selections, and does not copy fields or discover nested SDK surfaces. Migrated the Storage pilot so reads stay permission-free and writes require a token. Browser and Cloud package copy plans now carry the shared adapter. Split Storage composition into `src/browser/storage-adapter.js`; added one exact documented non-core-thin exemption for the shared adapter implementation.
- Evidence: focused bag/Storage/cloud-copy tests passed; TypeScript contract checks missing/forged permissions, unclassified names, invalid classification values, nested effects, and query signatures. Focused ESLint and `npm run tsdoc:check` passed. Full `npm run check` passed: 10 groups, 0 failed; local E2E 11/11; duplication 0 clones.
- Next-time guidance: migrate a second injected mixed filesystem bag (local document-store or build copy adapter), verify raw Node operations are only available at the environment boundary, then update the AllowEffects architecture examples.
