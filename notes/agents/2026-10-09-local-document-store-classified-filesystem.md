# Local document store classified filesystem adapter

- Unexpected hurdle: moving the mixed filesystem dependency into one bag made the local wrapper exceed the 50-line limit and no longer match the required thin `handle` wrapper form. The first sandboxed full check also could not spawn Node subprocesses (`EPERM`).
- Diagnosis: the thin check applies to the environment entrypoint, and the ordinary sandbox does not grant the process creation required by the repository gate. The separate non-core check showed the exact wrapper-shape failure; the restricted full check showed the process permission failure.
- Chosen fix: `src/local/documentStore.js` now classifies `readFile` as a query and `mkdir`, `rm`, and `writeFile` as effects with `adaptAllowEffectsBag`. Core receives the restricted `fs` bag and has no parallel raw method properties. Updated core fixtures and behavior assertions, documented the seam, and kept the environment wrapper below 50 lines in its expected handle form.
- Evidence: focused document-store suites passed (2 suites, 34 tests); `npm run tsdoc:check`, focused ESLint, and `npm run depcruise` passed. `npm run non-core-thin` passed (254 files, two existing explicit exemptions, 50-line maximum). Reviewed `npm run check` passed (10 groups, 0 failed; unit shards passed; E2E 11/11; `npm audit` 0 vulnerabilities; duplication 0 clones).
