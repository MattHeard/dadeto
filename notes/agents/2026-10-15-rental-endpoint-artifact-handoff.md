# Rental search endpoint artifact handoff

- **Unexpected hurdle:** The `gcp-prod` workflow successfully applied Terraform and produced `object_minute_rental_search_url`, then failed when `gh variable set` attempted to update a repository Actions variable. GitHub returned HTTP 403 (`Resource not accessible by integration`). The following static-site workflow also failed because the variable was empty (runs `38635166026` and `38657353798`).
- **Diagnosis:** The built-in workflow token can run Actions but does not have the repository Variables write permission required by that API. Adding more `actions` permission does not establish the separate Variables permission.
- **Chosen fix:** Stop mutating repository configuration from the GCP workflow. Validate the Terraform URL as HTTPS and upload it as the `object-minute-rental-search-url` artifact for 90 days. The static deployment workflow's manual dispatch accepts the GCP run ID, downloads `endpoint.txt`, and builds with that URL; push-triggered deployments continue to use the Actions variable.
- **Next guidance:** Do not trigger a production deployment without explicit authorization. Find a successful `gcp-prod` run with `gh run list --workflow gcp-prod.yml --status success`, then manually dispatch the static deployment workflow with `gcp_prod_run_id`. Verify the deployed browser-to-function flow before marking the Notion spec Implemented.
- **Evidence:** `npx jest --runInBand --no-cache test/scripts/netlify-prod-workflow.test.js test/scripts/gcp-prod-workflow.test.js` passed 2 suites / 5 tests. `DADETO_COVERAGE_SHARD_SIZE=80 DADETO_CHECK_TIMEOUT_MS=3600000 npm run check` passed all 10 gates.
