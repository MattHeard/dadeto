# Atlas bounded context presentation retrospective

- **Unexpected hurdle:** The context query already preserved contradiction edges and negative evidence, but consumers received one flat `items` array. The initial added cases pushed an existing test group eight lines over the lint limit.
- **Diagnosis:** `getEvidenceGraphContextV1` returns typed record items and raw relationship edges within one bounded page. Page size can leave an edge's endpoint record on a later page, so a presentation layer must retain the edge IDs and endpoints rather than trying to hide unresolved links.
- **Chosen fix:** Added `presentEvidenceGraphContextV1`, a pure page-level projection with separate hypotheses, evidence, experiments, and relationships. It preserves raw items, warnings, cursor, relation values, and endpoint IDs, and passes invalid context results through unchanged. Tests cover competing hypotheses with `supports` and `contradicts`, negative evidence staying in the evidence collection, an endpoint omitted by pagination, and invalid-query propagation. Split the new presenter tests into their own describe block to keep lint limits satisfied.
- **Evidence:** `npm run check:impact:run -- --files src/core/interpretability/index.js test/core/interpretability/graph.test.js test/core/interpretability/testZodContract.test.js` passed 9 suites / 87 tests, with no uncovered lines or branches in changed-core `index.js`; ESLint, core-parse, and duplication passed (0 clones). `npm run check` passed all 10 fast local gates with the same 9 suites / 87 tests; audit found 0 vulnerabilities.
- **Next-time guidance:** Build any browser view on this page projection while preserving relation endpoints across pagination. Keep hypothesis records, evidence records, and relationship polarity visually separate; don't infer a missing record from a missing page item.
