# THREEFOLD resolved scene layout

- Unexpected hurdle: the first coverage run showed that the resolver's defensive entity lookup branches were unreachable by construction, while malformed-input branches were not covered. A test also assumed a 3-cell authored building occupied one cell at scale 0; the logical projection correctly retained its 3×3 footprint.
- Diagnosis: `resolveSceneLayout` filters the canonical entities using hierarchy-visible IDs and then calls the deterministic `layoutScene`; every resulting layout ID necessarily exists in the source and layout maps. The coarse geometry is derived from the authored world bounds at the requested scale.
- Fix: compose semantic hierarchy and geometric layout while keeping their parent fields separate; use the resolver in the Broken Gate render path, preserve source draw order for projected render entities, and cover malformed input, nested thresholds, proxy outcomes, conflict/overflow propagation, permutation, immutability, and flat-scene rendering.
- Evidence: focused `npm run check:impact:run -- --files src/core/browser/game/threefold/logical-grid.js src/core/browser/game/threefold/renderer.js test/core/browser/game/threefold-logical-grid.test.js test/core/browser/game/threefold-renderer.test.js` passed 28 suites / 360 tests, ESLint, core-parse, zero clones, and 100% statements, branches, functions, and lines for both changed core files. `npm run check` passed all 10 gates; build and exact-head CI remain to be recorded.
- Next guidance: keep semantic hierarchy authored per scene only after its interaction and asset boundaries are specified. Continue the Rank 1 campaign work in small merged slices; the resolved layout API does not complete the broader THREEFOLD acceptance criteria.
