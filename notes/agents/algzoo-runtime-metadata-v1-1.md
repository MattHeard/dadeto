# AlgZoo protocol v1.1 runtime metadata

- **Unexpected hurdle:** the prior manifest treated hosted investigator/evaluator revisions and tokenizer hashes as pinned, while the approved Codex CLI subscription runtime does not provide those hosted attestations.
- **Diagnosis:** distinguish the immutable local AlgZoo fixture and deterministic evaluator from the mutable remote investigator. Preserve the requested model identifier as configuration and explicitly store a null backend-reported identifier when the CLI does not expose one.
- **Fix:** protocol 1.1/schema 2 records Codex CLI version, requested model identifier, observed timestamp, explicit unavailable backend identity, and the same runtime configuration in both paired arms. The evaluator remains local and hash-pinned; missing or malformed runtime metadata blocks readiness. The investigator adapter takes its model request from the per-session frozen configuration.
- **Evidence:** four focused Jest suites passed 50 tests; scoped `npm run check:impact:run -- --files src/core/interpretability/algZooPilotHarness/index.js test/core/interpretability/algZooPilotHarness.test.js` passed ESLint, core-parse, duplication and selected tests (9 suites/56 tests), with no uncovered changed-core lines or branches. Elevated `DADETO_CHECK_PROGRESS_INTERVAL_MS=3000 npm run check` passed all 10 gates over six serial shards (7,643 tests); `npm run build` passed. No Codex run, credentials, inference, held-out access, hardware action or spend.
- **Next guidance:** this only reconciles protocol/runtime metadata. Keep the scientific pilot on hold until the Pi runtime, enforceable isolation, frozen snapshot, audit store and live canary gates are verified; do not infer that subscription-authenticated runtime identity is a hosted-model attestation.
