# get-author-uuid-v2 plan workflow loop

- **Unexpected hurdle:** The existing `gcp-prod` workflow applies the full production Terraform plan, and a successful `gcp-test` run triggers it. Terraform also receives the OAuth client secret as a variable that is not marked sensitive, so printing the plan could expose it in Actions logs.
- **Diagnosis:** Traced workflow triggers, production variables, Terraform dependencies, and the exact function, invoker, and static-config resources. The Codex shell could not inspect GCP auth because its read-only SDK config rejected credential-store access; no direct GCP connector is available.
- **Chosen fix:** Added a manual, `main`-only, plan-only workflow targeting the get-author function, its approved `roles/run.invoker` binding, and the browser URL config. The raw plan and text output stay on the ephemeral runner; the job summary emits only resource addresses and actions. It does not touch the separate endpoint-registry spec or apply Terraform.
- **Evidence:** The workflow YAML parsed; the plan-summary `jq` filter produced only the expected address/action; `git diff --check`, targeted ESLint, and the focused Jest suite (1 suite, 3 tests) passed.
- **Next time:** Dispatch the plan-only workflow and review its resource summary. Keep production apply and the configured-site smoke check separate; inspect the reviewed plan before applying through an authorized path.
