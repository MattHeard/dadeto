# Atlas permission-aware research service — 2026-10-20

- **Unexpected hurdle:** The new service needed exact JSDoc types from existing graph APIs. The first aggregate run also found duplicated bundle-loading code, and the shared wrapper's conditional return was classified as parser logic by the core boundary check.
- **Diagnosis:** Broad `Record<string, any>` declarations hid required schema and request fields. Repeated load/validate branches crossed the clone threshold. The parser classifier treats a conditional return as parsing logic even when it only routes an already-parsed result.
- **Chosen fix:** Derive schema, query, submission, and result types from the existing API signatures. Add a permission-aware service over injected load/save adapters, centralize bundle loading and validation, and bind persistence into a small writer factory. Use explicit early returns. Tests use the fallback-capable schema test double, an in-memory adapter, and deterministic fake inference; no live inference or external storage is called.
- **Evidence:** `npm run test:impact -- --files src/core/interpretability/researchService.js test/core/interpretability/researchServiceV1.test.js` passed 8 related suites / 60 tests. `npm run check:impact:run -- --files src/core/interpretability/researchService.js test/core/interpretability/researchServiceV1.test.js` passed and reported no uncovered lines or branches in the changed service. `npm run tsdoc:check` passed; `npm run duplication` reported 0 clones; `npm run agents:reuse-report` accepted 9 valid events. Final `npm run check` passed all 10 fast local gates; its conservative fallback passed 976 suites / 6,812 tests. This is local evidence; exact-head Full Check remains the authoritative CI result.
- **Next-time guidance / open question:** Keep adapters at the boundary and pass the same `AllowEffects` token through every injected read and write. Select a concrete persistence adapter and authorization policy in a separate loop before adding production storage or public endpoints.
