# Stripe webhook raw-bytes enforcement (2026-10-11)

- Unexpected hurdle: ephemeral test environments accepted unsigned webhook fixtures and serialized parsed `request.body` when raw bytes were absent, contradicting the billing spec. The cloud E2E depended on this bypass, and the test runner had no webhook secret.
- Diagnosis: the Cloud Run function correctly verifies Stripe events when given raw bytes, signature, secret, and SDK verifier, but the `t-*` fixture branch skipped signature verification. The Playwright job already uses the test-only Secret Manager secret, while its service account lacked access.
- Fix: removed the unsigned environment branch and parsed-body serialization fallback. The cloud E2E now HMAC-signs the exact JSON string it transmits. Terraform grants the Playwright service account access only to the test webhook secret and injects that secret into the job.
- Evidence: focused webhook/simulator/infra tests passed (4 suites, 36 tests); TSDoc and scoped ESLint passed; cloud Playwright discovery lists all 11 cloud tests; `npm run build:cloud` passed; `terraform fmt -check -diff infra/playwright.tf` passed; elevated `npm run check` passed all 10 gates, 100% lines/functions/statements/branches, 11/11 local E2E, 0 clones, and 0 audit vulnerabilities. The full check is captured in the bead comment; coverage artifact: `reports/coverage/coverage-summary.json`.
- Limitation: local `terraform validate` is blocked by the machine's Terraform wrapper, which permits formatting only. The `gcp-test` workflow is the named deployment validator; it was not triggered from this loop.
- Next guidance: any webhook integration fixture must sign the exact transmitted bytes. Keep Stripe HTTP verification in the cloud adapter and the local simulator's generic payment-domain handler separate.
