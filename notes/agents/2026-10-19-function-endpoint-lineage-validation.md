# Function endpoint deployment lineage validation

- **Unexpected hurdle:** Rank 2's production registry publication and Netlify deployment had completed, but the Section E inventory still described the registry as plan-only. The new validator also needed to avoid introducing a second parser for the Rank 2 registry schema.
- **Diagnosis:** The available deployment evidence can be represented and checked offline, but the repository still lacks a collector that joins GCP workflow metadata, the public GCS object version, and the later Netlify deployment. An offline validator can establish the contract without claiming collection or endpoint health.
- **Chosen fix:** Added `src/core/build/function-endpoint-lineage.js` and regression tests. The validator requires a successful GCP apply, source commit and deployed function URLs; checks the configured stable registry URL, exact object body, schema/environment/function map and optional generation/ETag; then requires a later successful Netlify build with the same source commit and registry digest. Registry parsing reuses `parseFunctionEndpointRegistry`.
