## Prelaunch readiness audit — 2026-10-20

- **Unexpected hurdle:** The repository has a deterministic plan and injected adapter interface, but no AlgZoo investigator/scorer implementation or pilot run store is wired to it. The current process also has no provider, pilot, or spend configuration variables.
- **Diagnosis:** `src/core/interpretability/algZooPilotHarness/index.js` requires callers to inject `runInvestigator`, `scoreBlindedSubmissions`, and `hashMapSnapshot`; `runTargetPair` returns records in memory and does not persist them. `createAlgZooPilotSessionRecord` compares measured costs with caps only after an investigator call returns, so it cannot stop an over-budget call while it is running. The launch-ready value is derived from two booleans supplied in configuration; the harness does not execute or verify the canary access-control probes. No AlgZoo-specific project, database, or persistence configuration was found in the source, tests, docs, or workflows.
- **Pinned inputs confirmed:** The preregistration was first added at commit `f72b61807829fc4ed3c0a4a159a69cb356bea5ad`, and its current SHA-256 is `52acafc4e5ce9947cd6d4aa3f024f6eed52b3ceaaab318f63604c36203c92e17`. The fixture at `test/fixtures/interpretability/alg-zoo-m16-10.json` has SHA-256 `7ee224755483e714ae3c962b9846d5403f6c8245ca0497c57c3e0be00df9ee66`; its pinned source revision and checkpoint hash are checked by the harness. No live launch manifest was generated, and no assignments, inference, or outcome access occurred.
- **Exact setup required before a live pilot:** (1) choose a dedicated non-human investigator and evaluator provider/runtime with immutable model revisions and a secret-managed credential; (2) pin and hash the target/evaluator code, tokenizer, prompts, tools, dependencies, map schema, common-background bundle, and fixture; (3) provision a dedicated isolated project/store with append-only run records, separate investigator/evaluator permissions, and held-out data inaccessible to investigators; (4) implement adapters that persist every attempt, cost, access receipt, and blinded score, and enforce token, elapsed-time, tool-call, forward-pass, and monetary caps during each call; (5) implement and record successful control-canary and future-treatment-canary denial probes; (6) prepare all preregistered seed commitments and held-out commitments without exposing held-out values; and (7) approve an explicit total monetary ceiling for the complete run before generating/committing the launch manifest or assigning targets.
- **Chosen fix:** Keep the pilot at prelaunch. The committed harness and preregistration are the reusable artifacts; no provider call, target assignment, store write, or spend was made. Once every item above is available, create a separate bounded launch-readiness loop that verifies the pinned manifest and access controls before any inference.
- **Next-time guidance / open question:** The current harness's `launchReady` flag is metadata only, and its session budgets are post-call accounting. Do not treat either as a live launch safeguard. Do not pass held-out data into an investigator adapter, even for setup probes.
